## Experiment: E-003 — HTTP Conditional GET (ETag/Last-Modified) for RSS feeds
- **Date:** 27.09.2026
- **Status:** completed
- **Theory:** _fetch_rss_feed() currently downloads the full XML body on every scan, even when the feed hasn't changed. Adding ETag/Last-Modified request headers and handling HTTP 304 responses eliminates redundant data transfer. Most modern RSS servers support conditional GET. A per-session cache in HaberKuratorCore stores (etag, last_modified) keyed by feed_url.
- **Hypothesis:** H-003: "conditional_get_success_rate >= 0.50"
- **Measurement Metrics:** conditional_get_success_rate >= 0.50 (at least 50% of tested feeds return 304 on repeated request within a short window, meaning the server supports conditional GET)
- **Experiment Design:** For each tested feed: (1) Send normal GET, capture ETag + Last-Modified from response. (2) Resend with If-None-Match + If-Modified-Since. (3) Record whether we get 304 Not Modified (bandwidth saving) or full 200 body. Metric = ratio of feeds returning 304 on step 2.
- **Sample Size n:** 8 feeds tested
- **Code Scope:** haber_kurator_core.py (HaberKuratorCore._fetch_rss_feed)
- **Raw Results:** measured=1.0; n=8
- **Uncertainty:** none (n=8, 95% Wilson lower bound 0.68 >= threshold 0.5)
- **Metric:** consistent (measured conditional_get_success == claimed conditional_get_success)
